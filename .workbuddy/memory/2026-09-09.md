- 验证结果：后端 112 项 pytest 全绿（langgraph 实际装到 1.2.11，与代码兼容）；
  TestClient 全接口 200；next build 通过；smoke 16/16 通过，服务运行在 8010 / 3010
- 踩坑记录（重要）：
  1. 8000/3000 被「智能洪水预报系统」长期占用 → 脚本改为按签名识别服务身份，是自己的就复用，
     是别人的自动避让到 8010/3010，**绝不误杀**其他项目进程
  2. 环境存在 HTTP_PROXY 代理 → curl 访问 localhost 被劫持，脚本内所有 curl 必须带 `--noproxy '*'`
  3. Windows Git Bash 的 nohup 子进程会随脚本退出被回收 → Windows 分支改用 PowerShell Start-Process
  4. Start-Process 遇到环境里大小写重复的变量（NO_PROXY/no_proxy、HTTPS_PROXY/https_proxy）会抛
     ArgumentException → 启动前用 `env -u` 剥离代理变量
  5. `chcp` 是 cmd 内部命令，在 PowerShell 中不存在，写进 -Command 会整条失败
  6. `cmd /c npm` 拿不到注入的 PATH → 改用 `node.exe node_modules/next/dist/bin/next dev -p PORT` 直接启动
- 遗留：npm audit 报 5 个漏洞（4 high / 1 critical）；仍无 CI；migrations 重号未修

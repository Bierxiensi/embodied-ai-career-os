### 滑期算法口径（落到 overview）
```
completed = 满足 status∈(done,compressed) 且 seq<=view_seq 的天数
behind   = max(0, view_seq - completed)          # 落后几天
is_missed= (seq<=view_seq) 且 未通过              # 标红待决策
```
"通过"判定两条路：`day_progress.status∈(done,compressed)` 或 四件套齐全（与 /today 一致）。
`?day=N` 覆盖 view_seq（回看/测试用），不改 day_index 的日历含义。

### 三决策（POST /api/plan/progress，幂等 upsert）
- done：写执行日期，note 可选
- compressed：写执行日期，note 必填（压缩：验收降级速通）
- deferred：清空执行日期，note 必填（顺延：推后手动补，**不自动顺延后续天**）
- skipped：清空执行日期，note 必填（放弃：释放时间）
- pending：复位（清理用）

**硬约束**：落后时页面把标红日期交给用户手动选一个，决策必落 `deviation_note`；平台绝不自动顺延。

### 踩坑（已修）

  已在 `plan.py` 的 day_progress import 补回 `PROGRESS_PENDING`。
- 前端 `PlanBoard` 一处 `deviationNote: ... || null` 对 `string|undefined` 参数类型错，

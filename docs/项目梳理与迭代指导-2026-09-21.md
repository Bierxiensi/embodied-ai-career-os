### 2.2 核心价值主张（不变的内核）

系统不记录学习笔记，**管理能力成长**，每天回答三问：

1. 我距离目标还有多少差距？（SkillRadar + 严格口径达标率）
2. 今天唯一最能提升目标的行动是什么？（/today + ROI 排序）
3. 我的能力是否真的提升了？（L1–L4 证据门控，防虚构）

四个已落地的差异化设计（09-20 审计确认）：

| 设计 | 位置 | 价值 |
|------|------|------|
| **数据单一源** | `skill_profile.py`（49 技能）+ `target_roles.py`（赛道） | 改配置不改代码，杜绝多源漂移 |
| **证据门控等级** | `core/evidence.py`（L1–L4 纯函数） | "知道"≠"能证明"，简历防虚构的技术实现 |
| **阶段模式** | `career_mode` 模块（job_hunt / long_term_transition） | 一个北极星，切换不删历史 |
| **规则引擎优先** | 引擎独立纯规则模块，LLM 只做措辞增量 | 无 LLM 配置时全功能可用，可解释、可测试 |

### 2.3 对"这个人"的价值（为什么值得继续投入）

| 价值维度 | 论证 |
|---------|------|
| **注意力分配器** | 三线并行（答辩/博士/内核突击）下，唯一稀缺资源是每天 4-6 小时。OS 的本质是把注意力分配从"感觉"变成"系统输出"（v2.1 的 ROI 排序是这一价值的显式化） |
| **防虚构护栏** | `resume_facts` 锚点 + 证据门控，直接对冲"知道名词但讲不透"的面试暴露风险（09-08 已验证过代价） |
| **闭环放大器** | JD→证据→行动→面试反馈闭环，让每次面试失分自动转化为下一轮任务 |
| **Portfolio 本身** | 这个系统（FastAPI+Next.js+规则引擎+证据门控）就是一个 Agent 工程作品——用 vibecoding 建职业 OS，项目即能力证明 |
| **博士申请基建** | 10 月必须建导师库，PhD 模块（六维匹配+联系倒计时）是唯一从零的大块，也是时间最敏感的 |

### 2.4 价值的边界（诚实评估）

- **匹配分≠结果**：华夏泰科看板 82/A 档仍被拒。看板分数是"推进度"不是"达标度"（严格口径 llm 13% 达标）。**这是当前最大的口径风险，也是改造重点。**
- **系统不替代投递**：30 天窗口曾出现"课程推进了、里程碑 V0–V4 全未启动"的编排冲突。工具再好，不喂真实数据（JD、面试记录）就是空转。
- **内核层缺口系统填不平**：1.38→4 的差距要靠 Mini Post-Training Lab 的真实实验，不是靠刷题库页面。

### 3.2 低端模型（hy3 / deepseek-v4-flash）协作指南

#### 核心原则：低端模型只做"翻译"，不做"决策"

所有架构决策已冻结在 PRD/DEVELOPMENT_PLAN 里。低端模型的任务是**把明确的 spec 翻译成代码**，并跑通门禁。因此每个任务的 Prompt 必须是四元组：

```
【目标】一句话，做什么
【改动文件】绝对路径清单，只许动这些
【验收命令】可直接复制的命令 + 预期输出
【禁止事项】不许碰的东西（见 3.2.3 防坑清单）
```

#### 3.2.1 任务分级（按模型能力匹配）

| 级别 | 任务类型 | 适配模型 | 示例 |
|------|---------|---------|------|
| T0 | 零代码配置修改 | 任意低端模型 | P0 的 presets.py 填空、target_roles.py 加 phd 赛道 |
| T1 | 单点 bug 修复（已有明确诊断） | 任意低端模型 | D3 的 Pydantic 回落、D2 的语法错修复 |
| T2 | 标准 CRUD 模块（有模板可抄） | deepseek-v4-flash | PhD 的 models/schemas/api，抄现有 job_posting 模块结构 |
| T3 | 纯函数 + 测试 | deepseek-v4-flash | risk.py 七维、career_roi.py 公式 |
| T4 | 前端组件（>200 行） | **不建议低端模型**，或拆到 <150 行/组件 | RiskRadar.tsx 参照 SkillRadarCard 抄改 |
| T5 | 架构/口径设计 | **禁止低端模型** | 匹配分口径重构、迁移方言收口 |

**经验法则**：给低端模型的任务，验收必须是**机器可判定的**（命令跑过=对），而不是"看起来合理"。凡是需要品味、口径裁决、跨模块一致性的，留在高端模型或人工。

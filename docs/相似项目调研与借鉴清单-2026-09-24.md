## 一、当前功能设计评估

### 1.1 对照「三问」的逐问评估

**问题一：距目标岗位还有多大差距？——设计最完整，但数据可信度打折。**

现状盘点显示这一问的基础设施相当扎实：双轨就绪度（`services/readiness`，/job-hunt 与 /transition/dashboard 同源）、六维能力雷达（skills/domains 六域聚合）、技能依赖图（52 条 skill_dependency）、JD 匹配双轨（match_pct + strict_pct）、Career ROI Top5——从「差距在哪」到「补哪个收益最大」的推理链在代码层是闭合的。结构性问题有两个：其一，差距的另一端（目标岗位侧）数据失真——六维博士匹配引擎 X4 未裁决（`_timeline_score(None)` 返回 70 分，越不录截止日排名越靠前），且 phd_advisors 占位、contacted 全 0，学术线的「差距」是虚的；其二，匹配与就绪度的输入证据偏弱（见问题三），分数在算但支撑它的证据量不足，属于「可信的机制、薄弱的地基」。

**问题二：今天该学什么？——入口最好，供给最差。**

/today 的今日施工单是三问中承载最好的一问：四件套计数 + 七维风险 + ROI Top5 并行取数，PlanBoard 滑期横幅、DayProgress 手动决策都在。但「学什么」之后紧跟的「用什么学」几乎断供——ResourceList 硬编码仅 3 条资源（其中 2 条 huggingface.co 经代理 502 打不开），后端 RESOURCE_LOCK 的资源面远大于前端可点面；/knowledge 只能检索已入库 10 篇论文，无导入、无推荐、无学习路径。更关键的是生成能力埋没：「生成今日任务」（Planner）按钮藏在 /agents 页的 SubNav 里，主行动页 /today 没有生成入口；且 planner 默认 `generator=rule`，LLMGenerator 三处默认全关（Y10），系统实际提供的「今天学什么」是模板规则推出来的，不是理解你现状后生成的。

**问题三：能力是否真提升？——设计意图最完整，实测空转最严重。**

这是三问中设计投入最大、现实落差也最大的一问。证据链在四层互相咬合：LearningLog（反思式输入，注释明言「未来作为 Portfolio 能力证据」）→ DayArtifact 四件套 + auto_verified（「从展示变学习的核心机制」）→ SkillAssessment（old/new level、confidence、evidence_score 全程可追溯）→ skills.evidence_gate + core/evidence.py 的 L1-L4 晋级阶梯（能解释→能实现→能实验→能研究）。整条链每一环代码都在。但实测断在中段：**day_artifacts=0、day_progress=0、experiments=0**，L2/L3/L4 门全部不可达，全库 evidence_gate 最高仅 1；interview_questions 147 题 `is_verified` 全 0；commit_suggestions=0 且 `.github_last_sync` 水位文件不存在（GitHub 同步从未成功产出）；reviewer 证据评分的唯一前端调用方 TaskCompleteForm 在死组件子树里。结论直接对应自诊痛点(2)：**证据成长系统是一个空转的骨架**——不是设计错了，是输入端从未被真实使用、输出端接不到可达页面。

### 1.2 对照「伴随成长而非记录」的评估

**强项（值得保留的骨架）：**

1. **证据分层的意识是对的。** DayArtifact 的 auto_verified、SkillAssessment 的可追溯变更、ResumeFact 防虚构锚点（parse 只提 claims 不落库、diagnose 对照锚点标红）、Reviewer ≥80 才升级——这套「AI/登记产出不直接等于能力事实」的设计，与调研中 Friend-Xu 的 Fact Preservation、JobPilot 的 factuality guard、sean2077 的「五种命题互不冒充」是同构的，而且本项目做在数据模型层，比多数对标项目更早。
2. **单一真源的策略层。** `core/` 下 skill_profile（50 技能六域）、target_roles（四赛道 + TECH_BLACKLIST）、plan_30d（30 天脊梁 + 技能→课程日映射）、evidence、career_roi、risk 全部是纯函数/常量，LLM 路径全部「LLM 优先、规则兜底」。这是 Keep simple 信条执行得最好的一层。
3. **拒绝线执行得干净。** 全部 12 个对标项目涉及的反模式（自动投递、爬虫反指纹、无确认简历事实生成、求职期横向膨胀）在已拒绝清单里都有明文，且 resume 模块的实际实现与拒绝线一致。
4. **/today 的聚合取数模式**（5 个端点并行 + 各自兜底）方向正确，接近 FreeLingo 的「今日唯一入口」端点形态，只是还没收敛成一个端点。

**结构性问题（按严重度排序）：**

1. **输入端形状不对——登记式而非成长式（痛点 1 的本质）。** 64 个写端点中绝大多数是建档/登记型（phd 9、resume 7、interviews 7、milestones 4、paper 4），每日成长型入口实质只有 4 个：plan/artifacts、plan/progress、learning-logs、reviewer/review。其中 plan/artifacts 只写自动生成的 title（「Day 3 · 代码」），**无处填写这段代码解决了什么**——四件套登记的是「交了」，不是「学到了」。这正是 LearningLog 注释里承诺的反思式输入没能发生的结构性原因。
2. **死链路成片，「成长式」能力恰好全在死链上。** reviewer 证据评分（调用方死）、GitHub 建议确认流（githubService 零 import）、reports 日报周报反思闭环（仅死 ReportsBoard 引用）——三个最像「伴随系统」的能力全部不可达；反倒是纯登记式端点都活着。前端约 1/3 死代码 + 20+ 个不可达后端端点，是历次改版「建了不接、接了不删」的累积。
3. **编排链路与主轴脱节。** /api/agent/run 的 `_resolve_input()` 硬编码具身占位（planner 喂 Isaac 0→4、career 喂 Robot AI Engineer、research 喂 ACT），supervisor 路由表不含 knowledge（论文 Agent 编排不可达），三处过时人设 prompt（「具身智能学习导师」「机器人行业猎头」）与 Post-Training v3.0 口径冲突——多 Agent 层是整个系统里唯一还在输出旧方向内容的部分。
4. **认知负担无治理机制。** /today 一屏 6+ 卡片无主次、Sidebar 11 个入口 vs 每天 1-2 小时、顶栏侧栏模式联动不一致、Sidebar 缺 /today 条目、生成任务按钮放错页——没有任何类似 sean2077 的 context ladder / 停止规则、Friend-Xu 的 Attention 引导、Granit 的命令面板兜底来约束暴露面。
5. **文档口径三方打架，规划权威缺失。** 首页/北极星三份文档三种答案、默认模式过期未更、时间预算四套口径、每日三问三套版本、11 项矛盾挂账——这本身就是一个结构性问题：**重新规划前必须先裁决，否则任何新规划都会重演口径漂移。**

**总评：** 现状是一个「策略层和数据模型设计质量高于产品接线质量」的系统。三问中，第一问机制全但数据虚，第二问入口好但供给断，第三问设计最深但完全空转。最核心的错位不是缺功能，而是**已建成的「成长式」机制（证据门、reviewer、反思日志）全部卡在「无人输入」和「无处可达」之间**——重新规划的主战场应是接通与收窄，而非新建。

**逐项评述：**

**sean2077/career-os** 是与本项目方法论最同频的对标：不给功能清单，给治理结构。「七 Skill = 七个权威，跨域只允许一个 owner + 有界 handoff」直接命中本项目四线并行多头写入的病灶；「outcome-first + 到 decision-ready 就停 + 禁止因能力存在就派 reviewer」是对 token 和认知预算的显式治理——本项目 LangGraph 有 6 个注册 Agent 却没有任何停止规则。其 reviewer 只读、契约 JSON、非法输出 fail-closed 且不得成为第二写入方，恰好可以修正本项目 reviewer 同时评分又写库的隐患。它已替本项目验证了「证据成熟度/就绪度/外部结果分离声明」的价值。反面是框架仪式感过重（四区所有权、SBOM、PGP、双仓拓扑），对单人 Keep simple 项目是过度工程——借边界思想，弃治理排场。

**Friend-Xu/career-os** 给出了本项目已声明但未落地的范式的完整工程实现：事实层 schema/parser/apply 级禁止 AI 修改（而非运行时拦截），AI 只能走 Proposal 通道，用户确认后 append-only 应用。这与「拒绝未经人工确认的简历事实生成」完全同构，且落点明确（提案表 + 确认后落库）。其「画像状态驱动 Next Action + Attention 三件套（浮层/角标/空态 Action）」正面回答「每天 1-2 小时不知从哪开始」；其八条质量原则做成「原则×模块×强制机制」三列表，是把三问从愿景变成模块级强制条款的样板。风险是 203 个 TS、119 RPC、M1-M6.5 + ADR 的单人工程面——与本项目信条直接冲突，机制要、排场不要。

**jobseeker-analytics**（202 星，唯一有真实用户验证的项目）证明了一条本项目已局部验证的路径：**最好的记录是自动生成的**。GitHub commit 同步是本项目唯一「事件流→产出自动（auto_verified=True）」的成功先例（虽然实际从未跑通），它把这个范式推广到投递/拒信/面试邀约邮件。其窄过滤器 YAML 公开可审计 + 只存五元数据、正文永不存储的契约，是读个人数据时建立信任的标准答案。漏斗状态机（含 Hiring Freeze 这类真实阶段）让「差距在哪」变成一眼可见的卡点。红线提示：Gmail 全量 OAuth 是高风险基础设施，本项目做同等透明度设计前不应碰；但「用户主动转发一条邮件→半自动回填投递状态」这类窄版本不越线。

**Learn FASTER**（379 星）用最少的代码回答了三问：/learn=今天学什么、/review=复习什么、/progress=能力是否提升——三个命令就是产品三问本身，这是对本项目 64 端点暴露面最尖锐的讽刺。Teach-Back 机制（学完教练主动发起口述→三选一→自动写入复习调度）把「用户来登记」翻转成「教练发起问答顺便完成写入」，是破解痛点(1)(2) 的最具体配方。它还工程化地处理了「教练静默失效」（resume 强制重传 system prompt + 23 个回归测试）——本项目三处过时人设 prompt 正是同类问题。红线：不要把 coach 人格寄托在 CLI flag 上，要在 LangGraph state 里持久化并加测试。

**FreeLingo**（133 星，栈与本项目几乎同构：FastAPI + Next.js，且当天仍在发版）的三个机制都可直接平移：① GET /today 单端点聚合（解析计划→推进进度→定位当前 slot→复用或生成），前端不做状态编排——本项目 /today 已并行打 5 个端点，收敛成一个正是既定方向的完成态；② 确定性网格（计划不调 LLM、可预测、容量可校验）+ 懒生成内容（打开当天才生成并持久化）——30 天计划已经是确定性脊梁，缺的是「打开才生成」的个性化层；③ assert_plan_capacity 容量预检——把「每天 1-2 小时」从软提醒变成新计划创建前的硬约束，直接治理四线并行把人压垮。其 specs/*.instructions.md（frontmatter applyTo 绑代码路径）是防 AI vibe-coding 漂移的低成本护栏。反面：AGPL 传染、PG+Redis 部署面、商业化多线——都不要。

**Skill-Anything**（333 星）补的是本项目最薄弱的供给端：资料→掌握单元（12 节学习包 = 摘要/概念图/详解/测验/闪卡/练习/路径），而不是资料→摘要。本项目论文 RAG 停在「存 PDF + 向量 + 能问答」，没有把 10 篇 Post-Training 论文加工成可练习的掌握单元——这是痛点(3)「不知道学什么资料」的供给侧答案。pack.yaml 单一数据源 + 按节配额 + 覆盖率自检 + 两级模型路由（FAST 跑 map / SMART 跑 reduce）+ sha256 缓存 + 无 key 降级规则生成，每一项都适配 1-2 小时/天的成本约束。反面：功能面横向铺（repo/音频/视频）但深度停在「生成即止」、无复习调度闭环——本项目已有雷达和 reviewer，掌握单元的练习结果应直接回流，不要学它只做一次性生成。

**Pluto-Mo/personal-career-os** 的「经历只沉淀一次，之后每个 JD 自动调用」是治理 64 个登记式写端点的形状答案：写端收敛为少数 intake 形状（进来→diff→确认→落库），读端（施工单/雷达/评分）全部从事实库派生。其意图门控（「研究/分析」默认只读，明确说「投/生成」才写）让系统敢被随手问而不产生垃圾数据——本项目大量测试专用端点和零消费端点正是缺这道门。「素材缺口如实说，做成之前一个字不写进简历」与缺口诚实原则直接可用。反面：纯文件堆无索引（本项目有 SQLite+RAG，不退回）、四格式全量产物、单场景窄化（本项目四线并行不能学它砍学术线）。

**JSE** 的可解释性工程最细：triage 快筛→证据锚定深析的分层评估（便宜先过滤贵的）、命名常数权重 + explain 出口 + clamped prior、结果先验三件套（≥5 样本才生效 + 维度 clamp + 单独永不触发否决）、<3 样本漏斗分段直接隐藏。这四条是「拒绝不可解释自动决策」信条的可执行规格——本项目任何「结果→反调学习计划/能力权重」的机制都应照此约束。fragment 证据库（历史材料切碎索引 + 面试到达即挖矿量化 claim 并加权）是「证据从登记字段变可组装资产」的范本。反面：爬虫生态、外联、自修复 scraper、Electron 重栈——全不要。

**JobPilot** 与本项目栈镜像（FastAPI+Next+LangGraph+pgvector），其 ATS 可解释打分四件套（keyword match / formatting / missing keywords / suggestions，另有 TF-IDF 无 LLM 降级）直接回答第一问——给缺失关键词清单而非裸分。三栏编辑器 accept/reject diff 是「AI 起草+人确认」的成熟交互外壳。Approval Centre 原则（drafts are automated, decisions are not）与本项目拒绝线同频。注意其自身教训：5-Agent 串行管线 + Playwright + Tectonic + 抓取层的膨胀使其停更——学其人审出口，不学管线长度。

**Northstar** 的 capture-first（raw 保留→AI 起草→人审→写入实体）是把 64 个写端点折叠成统一入口的输入管线方案；Life→Disciplines→Projects 脊柱是把四条线映射为 4 个 discipline、今日报只按脊柱聚合的减负方案；FSRS-6 间隔重复直接服务第三问（记住≠看过）。但其财务/习惯/IELTS/情侣工作区的横向膨胀正是本项目明文拒绝的路线，Java+三端+22 open issue 的维护面也不可取——取脊柱与调度，弃域扩张。

**Granit** 最值得借的是三个交互思想而非实现：① Daybook——当日唯一 source of truth，四线事项不各开页面、统一投影到一张今日单，勾选回写各线 canonical 记录（任务即源文档一行 `- [ ]`，十多种视图零复制）；② 自由语言写一天→确定性本地解析→agenda 精确预览→显式 apply（No model is required 的兜底）；③ 命令面板兜底一切不该占永久按钮的功能 + Home 只答 what matters now。这三点分别对应痛点(4)(5) 和「今天该学什么」的交互形态。TUI 载体、废弃双栈留仓、pre-1.0 铺重基础设施——都不要。

**notiapply** 整仓是红线反面教材（指纹绕 Cloudflare、全自动填表提交），仅两点可取：带失败态的状态机（review-incomplete/fill-failed 优雅退出，看板即系统真实状态）和 STYLE.md 把信条写成架构不变量（DB schema 是唯一真相、爬虫软失败、原子事务防悬挂）——后者恰好可把 Keep simple 从口号变成每次加模块前的对照门槛。

## 三、值得吸收的优点（按优先级）

**P0（先做，零代码或近零代码的裁决与治理）**

1. **停止规则 + 请求分类前置** — 来源：sean2077/career-os — 解决：痛点(4)(5)、answer-only 对话也落库的入口污染 — 落到：写端点入口守卫 + Agent 编排；LangGraph 每次会话只激活一个主 Agent，其余只返回记录 ID；研究/检索「信息开始重复即停，保留 unknown」 — 形态：**改架构（编排层加分类与停止规则，不新增端点）**。

## 四、明确不学的反模式

1. **爬虫/反指纹/自动投递**（notiapply Tier-4 Scrapling+Camoufox 绕 Cloudflare、JobPilot 抓取层、JSE scraper 生态）——本项目已明文拒绝，且合规与维护成本对 1-2h/天是纯负担。notiapply 全链路自动填表提交的形态是边界反面教材，一行不抄。
2. **读收件箱级授权**（jobseeker-analytics Gmail 全量 OAuth + 独立安全审计才上线的信任成本）——本项目不具备同等透明度工程前不碰；只做用户主动转发/主动粘贴的窄版本。
3. **求职期横向膨胀**（Northstar 财务/习惯/IELTS/情侣区、Granit 第二个 Obsidian 式功能清单、notiapply CRM+outreach+analytics、JobPilot 持续加模块至停更）——四线已是上限，不加第五条线。
4. **未经人审的 AI 直写事实**（FreeLingo LLM 自由写作/发音评分直接定掌握度、Northstar 宽自动化面）——一切能力判定必须过「AI 起草→人确认」或「可解释规则评分」，与拒绝线一致。
5. **框架/治理排场**（sean2077 四区所有权+SBOM+PGP+双仓、Friend-Xu 203 TS+119 RPC+ADR 体系、FreeLingo PG+Redis+商业化多线、notiapply 9 类技术 4 种语言）——单人 Keep simple，借机制不借工程面。
6. **重部署栈与桌面双运行时**（JSE Electron+Python 三平台 CI、notiapply Tauri+n8n+Tailscale、Northstar Java 三端）——Next.js+FastAPI+SQLite 已够。
7. **废弃双栈留仓**（Granit Svelte 旧 UI deprecated 仍留 web/）——本项目 redesign 迁移按 phase6 删旧，死组件/死 service/5 个 redirect 壳同批清理，不留「历史用户」借口。
8. **黑盒/自修改自动化**（JSE LLM 生成替换 scraper 代码、分发未签名 beta+SmartScreen 绕过指引、notiapply 全自动提交）——超出可接受自动化范围。
9. **一次性生成无调度闭环**（Skill-Anything 生成即止、无遗忘曲线）——掌握单元必须接复习调度与雷达回流，否则只是精致的登记。
10. **把教练人格寄托在脆弱注入面**（Learn FASTER `--system-prompt` flag，`--continue` 恢复即静默失效）——coach 指令固化进 LangGraph state/bootstrap 并配回归测试（本项目三处过时 prompt 就是未设防的实例）。
11. **引入对标项目为依赖**（全部 12 个均为单人小仓、多数 <400 星且部分停更）——只读机制，不 fork、不绑上游语义；AGPL（FreeLingo/GPLv3 Friend-Xu）代码一律不复制。
12. **为展示智能堆 Agent**（JobPilot 5-Agent 串行管线、Friend-Xu 自建对话协议栈）——与已拒绝的不可解释多 Agent 自动决策冲突；本项目 6 个 Agent 应收窄而非增加。

## 五、差异化机会

对标项目都没有打通、而本项目有条件打通的链路：

**机会一：JD→证据→补强行动→面试回流 的全链证据闭环。**
12 个项目各有一段：JobPilot/JSE 有 JD 匹配与打分但无学习侧；jobseeker-analytics 有投递漏斗但无能力证据；sean2077 有证据治理但无求职执行；Pluto-Mo 有事实库但无雷达。**本项目是唯一四段实体全在的**：JD 匹配（match/strict 双轨）+ 证据层（ResumeFact/SkillAssessment/evidence_gate L1-L4/Experiment）+ 补强行动（plan_30d + task_scope + ROI）+ 面试回流（interviews stats + to-tasks + 弱项排行）。缺的不是新建，是接线：面试弱项→自动映射技能缺口→生成补强任务→产出四件套证据→雷达/reviewer 更新→下一版简历 skill-lines（只收 gate≥1）自动变强。这条「面试暴露缺口→学习产出证据→证据刷新简历」的循环没有任何对标项目具备完整数据模型——**接通即差异化**。

**机会二：Post-Training 学习闭环（资料→掌握→证据→岗位差距）。**
对标里 Skill-Anything 有加工、Northstar/Learn FASTER 有调度、FreeLingo 有网格——但没有一个绑定在真实岗位主轴上。本项目已有：10 篇真实 Post-Training 论文 + 1591 条真嵌入 + LLM 成句问答 + 30 天 SFT→LoRA→DPO→GRPO 脊梁 + 六域雷达 + 四赛道靶向。补上掌握单元加工（P2-11）与间隔重复（P2-12）后，可做到：论文问答产出的概念自动进复习队列，复习/小测结果回流 evidence_gate，gate 等级决定能否进简历 skill-lines 和 JD 匹配加分——**「读过的论文」变成「可审计的能力证据」**，这是通用学习工具（Skill-Anything/FreeLingo）和通用求职工具（JobPilot/JSE）都不会做的交叉点。

**机会三：SO101 练中学作品化（冻结赛道的资产化，不占每日主线）。**
embodied 已冻结不占每日时间，但 SO101 回退学习法 + MISTAKES 错题集 + AI Coach 模式（baseline→动手改→错题沉淀）是已建的数据资产，目前是前端零页面的数据孤岛。差异化打法：不作为第四个日常入口，而是**作品证据工厂**——错题与 baseline 改造记录本身就是 engineering_delivery 域的 L2/L3 证据（code+commit→实验），经 packaging 的 README 13 节骨架直接组装成作品集项目，供 on-job 后转型具身或面试讲「工程能力」用。对标项目全是纯求职/纯学习工具，没有一个把「练中学的过程记录」转成「可展示作品 + 可晋升证据」——本项目的数据形状（MISTAKES/Experiment/DayArtifact/SkillAssessment）天然支持，只差一个展示与组装层。

**机会四（工程性差异化）：单人可信的「证据成长操作系统」。**
综合全部借鉴，本项目可以占据的独特定位是：一个**证据门驱动、schema 级防虚构、规则可审计、每天 1-2 小时容量预检**的职业成长 OS——sean2077 有治理没有产品，Friend-Xu 有事实保护没有学习侧，jobseeker-analytics 有自动记录没有证据层，Learn FASTER 有教练没有岗位主轴。把 P0-P2 接通后，「不是记录笔记，而是管理能力成长」这句信条才第一次有可运行的定义：**每一条能力主张都能点开看到证据（artifact_url/commit/实验/验收题），每一份证据都能点回它缩小的岗位差距**。

## 六、对「重新规划」的三种路线启示

**路线 A：收敛重定位（减法优先——砍端点、砍导航、砍死代码，把系统压回三问）**

应吸收：**P0-1 停止规则 + 请求分类**（sean2077）、**P0-3 意图门控**（Pluto-Mo）、**P1-7 三命令对三问**（Learn FASTER）、**P1-3/矛盾5 三问单一权威**、**P2-17 脊柱分区 + frozen 线降噪**（Northstar/sean2077）、**反模式5/7 拒绝排场与双栈**、**P1-style STYLE.md 不变量**（notiapply）、**四、12 砍 Agent 不加面**。
核心叙事：64→少数 intake 形状，11 入口→三问三入口 + CommandPalette，6 Agent→1 主 Agent + 停止规则，删除全部死组件/死 service/redirect 壳/零消费端点（或标注 deprecated）。这条路线与 Keep simple 信条和「功能建设已结束、边际价值来自接线」的阶段判断最自洽，工期最短，风险最低；代价是放弃了部分已建能力的展示面。弹药要点：对照表里每个高借鉴项目都自带「范围膨胀至停更」的反面实证（JobPilot/notiapply/northstar/JSE），收敛本身就是被验证的生存策略。

**路线 B：路线图重排（不改定位，重排施工顺序——先裁决、再接线、后补供给）**

应吸收：**P0-2/4 零代码裁决先行**（本项目 §12.7 + FreeLingo 容量预检）、**P1-5 Proposal 通道 + capture-first**（Friend-Xu/Northstar）、**P1-8 三死链接线**、**P1-10 Y9/Y10/prompt 清理**、**P2-13 事件流自动记录窄版本**（jobseeker-analytics）、**P2-14 /today 单端点**（FreeLingo）、**P2-16 漏斗状态机**（jobseeker-analytics/JSE）、**P2-22 信任即文档**。

**路线 C：体验与架构升级（交互与架构层的系统性换代——单入口、状态机、证据 UI）**

核心叙事：以 09-24 redesign 为底座，把「登记表单」交互整体升级为「教练发起 + 预览确认 + 状态推进」的伴随式交互；架构上做 /today 单聚合端点、applications 状态机、reviewer 契约化、掌握单元 schema 四个换代件。这条路线对「像记录系统不像伴随系统」的体感痛点打击最直接、演示效果最好；风险是工程面最大，若不同时执行路线 A 的减法，会重蹈「越升级越膨胀」的对标项目覆辙。弹药要点：必须与收敛措施捆绑承诺（新交互进、旧死链出，端点总数不增反减），否则违背 Avoid over engineering 信条。

**三条路线的关系供裁决**：A 是 B 的前置原则（B 的每一步都应按 A 的减法标准执行）；C 的多数部件可挂载在 B 的第 2-3 步上而不必单立门户。无论选哪条，P0 的四个零代码裁决（X4/北航/Y7/三问+时间预算口径）都是三条路线共同的第一步。

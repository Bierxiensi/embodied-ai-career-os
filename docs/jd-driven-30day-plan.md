## 0. 结论先行

**可行 —— 但它的作用范围是「决定学哪些」，不是「决定学到多深」。**

三点必须说清：

1. **v1 的「需新学 = 0」不成立。** 真 JD（id=7）一进来就长出 **3 个真缺口**（§2）。
   这恰好证实了 v1 §1 的警告：*当时的 75% 就绪度是「对比理想画像」算的，不是「对比真 JD 准入线」*。
   现在真数据把这句话兑现了 —— **这正是必须用真 JD 才做决策的理由**。
2. **缺口只有 3 个，且都能挂在现有课程两侧**（不用重建课程）：插 3 天即可，改动成本极低。
   JD 驱动在这里的价值是**排序 + 验收 + 取舍**，不是新增内容体系。
3. **有一个看不见的盲区**：JD 一半篇幅在讲知识图谱 / 信息抽取 / 语义对齐，而技能画像里
   **没有对应项** → 它既不算"已覆盖"也不算"待学"，**根本没被度量**（§3）。这是最该决策的地方。

## 3. 词表盲区 —— 比 3 个缺口更值得决策

这条 JD 的核心工作是：**标准文本结构化解析 → 20+ 维度标签抽取 → 标准-企业-产业知识图谱 →
实体对齐与关系推理 → 跨文档统一语义对齐**。

这些内容在 `SKILL_PROFILE` 里**没有任何对应技能项**。后果有两层：

- 它们**不会出现在 `gaps` 里** → 82 分看起来"没缺口"，其实是**没被度量**；
- 也**不能硬塞进 `required_skills`** → 引擎对未知技能名一律按 level 0 计，
  会凭空造出 `gap=4` 的假缺口，把分数打下去。

**建议：不补词表、不为此新增学习方向。** 三条理由：

1. **30 天主线是 LLM。** 知识图谱是独立方向（本体建模、图存储、图推理/图神经网络），
   3 天学不出能在面试里被追问三层的深度 —— 学了也是背关键词。
2. **铁律：单周学习/平台工时 ≤ 2 个晚上。** 加方向必然挤掉 LLM 主线，得不偿失。
3. **用户的真实强项本来就是这条 JD 的一半。** 招投标**文档结构化抽取 + 条款级比对**
   （抽取覆盖率 56%→90%、累计 3000+ 份）与这 JD 的"标准条款拆解、标准比对分析"
   **高度同构**；RAG（召回 56%→78%）、Agent（ReAct，覆盖率 56%→90%）也直接对得上。
   → **这条 JD 应该用「文档智能」叙事打，而不是用「知识图谱」叙事打。**
   硬补知识图谱是拿自己的弱项去碰最深的坑。

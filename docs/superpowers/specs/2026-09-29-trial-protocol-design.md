# 试用期协议设计（Trial Protocol）

> 2026-09-29 · 基于 brainstorming 产出 · 「先用真问题说话」——用一段真实使用期为下一阶段规划积累弹药
> 依赖：`2026-09-24-mastery-unit-dual-loop-design.md`（三计划已全部执行关门，523 passed / 四信号 E2E 绿）
> 关系：本协议**不建任何产品功能**；5 张后置票据保持绑定状态，不提前做

## 一、背景与决策记录

掌握单元双环三计划已收官（48 commits，终审全部 Ready-to-merge-Yes）。四条成功信号中两条是人工项（15 分钟体感、≥50% 覆盖率），且后置票据里多张是"用出来的需求"（体感埋点、覆盖率报表、evidence-gap→施工单项）。因此先跑一段真实使用期，基于真实问题再开下一轮 brainstorming → spec → plan。

| # | 决策项 | 结论 |
|---|--------|------|
| D1 | 本阶段主题 | **试用期方案**本身（怎么用、怎么记、何时回来规划） |
| D2 | 出口条件 | **信号 + 下限**：最短 14 天，之后「人工信号分支」或「问题分支」先满足先回 |
| D3 | 问题捕获 | **仓库错题集** `docs/试用错题集.md`（对齐 MISTAKES 文化，一行一条） |
| D4 | 协议形态 | **B 自查仪表**：`trial_status.py` 一条命令读信号 + 每周五自查表 |

## 二、出口条件（信号 + 下限）

**计时从 spec 提交日（2026-09-29）起，最短 14 天**（不足 14 天任何分支都不触发）。满 14 天后，满足以下**任一分支**即触发回炉复盘：

### 分支一：人工信号（两项都跑过）

- **M1 体感记录 ≥7 天**：每天一行自估「OS 操作耗时（分钟）」（从打开到收工，不含纯学习时间），记入错题集**每日体感表**（见 §四）。
- **M2 覆盖率爬坡读数**：每周五读一次核心题库 `is_verified` 覆盖率，**连续两次读数且后一次高于前一次**即算"跑过"。
  - **口径（钉死）**：分子 = `unit_items` 中 `kind='quiz_q' AND is_verified=true` 的条数；分母 = `kind='quiz_q'` 总条数。`interview_questions` 覆盖率属后置票据「覆盖率报表」，不在本协议分母内。

### 分支二：问题分支

- 错题集**有效条目 ≥10 条**（去重后；同一根因的重复现象算一条）。

> 达标类指标（如 ≥50% 覆盖率）**不在**本协议追踪——试用期只取"有读数、有趋势"，达标归属后置票据。

## 三、使用流与节拍

### 每日（不加新流程）

照 spec §3.2 既定流执行，协议不引入任何新页面、新表单、新步骤：

```
/learn 学单元 → 测验实证 → Teach-Back → /review 复习 10-15 分钟
→ ReviewBoard 写实质日志 →（系统外动手，commit 半确认）
```

### 每周五（5 分钟自查）

1. 跑 `backend/scripts/trial_status.py`（只读仪表，见下）
2. 在错题集**每周五自查表**追加一行（覆盖率读数直接抄脚本输出）

### 随时（问题捕获）

哪里不对劲，错题集一行记下（格式见 §四）。

### 仪表规格：`backend/scripts/trial_status.py`

- **只读**：仅查询，零写入（dev 库 `backend/data/app.db`）
- **输出五项**（单块文本）：
  1. `连续活跃天数`：从今天往回数，当天存在以下任一即算活跃——新增 learning_log / 新增 review_log / `unit_items.verified_at` 当日置位（naive UTC 按项目既有 normalizeUtc 口径折算本地日）
  2. `quiz 覆盖率`：§二 M2 口径的分子/分母/百分比
  3. `覆盖率历史读数`：错题集**每周五自查表**中已有的覆盖率读数序列及最近差值（表为空/文件不存在时输出「暂无历史读数」）
  4. `错题条数`：错题集中有效条目计数
  5. `到期卡数` + `最近自查日期`：`review_cards` 中 active 且 due≤now 的数量；自查表最近一行日期

## 四、错题集规格

**文件**：`docs/试用错题集.md`

**文件头 = 两张表**（粒度不同，各记各的）：

```markdown
## 每日体感（每天一行；M1 计数口径：本表有分钟数的行数）
| 日期 | 体感分钟 |
|------|---------|

## 每周五自查（每周一行；跑完 trial_status.py 后填）
| 周五日期 | 覆盖率读数 | 新问题数(本周) | 本周最卡的一件事 |
|----------|-----------|--------------|----------------|
```

**问题条目**（一行一条，追加在表后）：

```markdown
- [2026-10-01] 现象 | 卡在哪 | 猜测（? 可空） | 严重度(高/中/低)
```

- **现象先行**，不写感想；猜测可以填 `?`
- 同一根因的重复现象合并为一条（在原条目后补 `[+日期 附注]`）

**复盘关闭**（触发出口后、新一轮 brainstorming 时逐条处置）：

```markdown
- [2026-10-01] … → 转票据 <票名/或 本spec§五>
- [2026-10-01] … → 不修（原因）
- [2026-10-01] … → 已修 <commit>
```

## 五、边界（试用期明确不做）

1. **不写任何新功能**——5 张后置票据（半确认 suggestion UI、evidence-gap→施工单项、is_verified 覆盖率报表、rule→llm 真升级、卫生杂项批次）保持绑定状态，不提前做；体感埋点与覆盖率报表尤其不做（它们是"用出来的需求"）。
2. **不刷已知 debt**——41 处 legacy lint、portfolio 文案、EvidenceGateList 错误态 0 计数等，必须靠真实使用决定值不值得修。
3. **不开展内容建设**——讲义 3/30、语料扩充是用户并行的个人任务，不属本协议。
4. **分支去向独立处理**——merge/PR/保留/丢弃 4 选项与本协议互不影响。

---

## 六、复盘出口

任一分支满足（且满 14 天）→ 开新一轮 brainstorming：

- **输入**：错题集（含关闭处置）+ `trial_status.py` 汇总读数 + 每周自查表
- **产出**：下一阶段 spec → plan → 执行
- **中间无检查点**：每周五自查即唯一节拍，不设周会

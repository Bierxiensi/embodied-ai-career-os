## 二、项目目标与价值（在 v2.1 收口后的重新定位）

### 2.1 命题一实测：输入面其实**很大**，问题是输入的"形状"不对

实测 （脚本 `.workbuddy/tmp/audit_input_surface.py`，可复现）：

**总写端点 64 个 / 总读端点 51 个**，按模块：

| 模块 | 写 | 读 | | 模块 | 写 | 读 |
|------|----|----|---|------|----|----|
| phd | 9 | 5 | | job_postings | 3 | 2 |
| interviews | 7 | 4 | | practice | 2 | 2 |
| resume | 7 | 4 | | tasks | 2 | 1 |
| milestones | 4 | 0 | | agent / career / career_mode | 1 each | 1-2 |
| paper | 4 | 2 | | learning_logs | 1 | 1 |
| plan | 4 | 3 | | planner / reports / reviewer | 1 each | 0-5 |
| projects | 4 | 3 | | skills / tools | 1 each | 1-5 |
| experiments | 3 | 2 | | dashboard / job_hunt / risk / transition | 0 | 1 each ← 只读 |

**三个"看起来只读"的页面其实都可写**（这是判断①不成立的关键）：

| 页面 | 已存在的写端点 | 前端是否已接 |
|------|----------------|--------------|
| 今日施工单 | `POST /api/plan/artifacts`、`DELETE /api/plan/artifacts/{id}`、`POST /api/plan/progress`、`PATCH /api/tasks/{id}/status`、`POST /api/plan/commits/sync` | ✅ 已接（`createArtifact`/`deleteArtifact`/`updateTaskStatus`/`syncCommits`） |
| 计划页 | `POST /api/planner/generate` | 部分 |
| 练习 / 小测验 | `POST /api/practice/practice`、`POST /api/practice/quiz/start` | ✅ 已接 |

**那为什么你会觉得"没地方输入"？** 因为 64 个写端点里，绝大多数是**登记式输入**（建岗位、建博士目标、建项目、建简历版本）——它们服务于"建档"，不是服务于"成长"。而唯一的**每日入口**（今日施工单）虽然能写，但写的是**布尔值**：

```tsx
// TodayBoard.tsx:96-102 —— 点一下四件套，发生的事：
createArtifact({
  planDayId: day.id,
  kind,                                  // 只有 4 种：代码 / 笔记 / 面试题 / commit
  title: `Day ${day.seq} · ${meta?.label ?? kind}`,   // ← 标题是自动生成的
});
```

也就是说：你点一下"代码 ✓"，库里只多了一条 `title = "Day 3 · 代码"` 的记录 —— **没有地方写"我今天写的这段代码解决的是 DPO 的 loss 不收敛"**。这就是"记录系统"体感的真正来源：

> **它记录的是状态（勾没勾），不是实质（做了什么）。**
> 而 `day_artifacts = 0` 这个数字说明：连"勾一下"这件事，你都一次没做过 —— 因为勾了也留不下任何东西。

### 2.2 命题二实测：知识库的"98 篇"是重复出来的假象（🔴 本轮最重要发现）

我在 v3 之后对知识库做过一次乐观判断（"RAG 管线已经打通"）。本轮实测**推翻了这个说法**：

**接口层：✅ 完全能用（实测原始响应）**

```
GET  /api/paper/stats  → 200
  {"paper_count":98, "chunk_count":583, "indexed_chunk_count":577,
   "model_name":"hash-384", "coverage":0.9897}

POST /api/paper/ask   → 200
  {"question":"什么是 self-attention？",
   "answer":"[introduction] Visuomotor policy learning has become a key approach
             for robot manipulation. However, deterministic policies struggle
             with multimodal action distributions..."}
```

**数据层：❌ 98 篇是假的 —— 去重后只有 3 个标题**

| 标题 | 行数 |
|------|------|
| ACT: Action Chunking with Transformers for Imitation Learning | **90** |
| Diffusion Policy: Visuomotor Policy Learning via Action Diffusion | **7** |
| Test Paper for VectorStore | 1 |

规律很清楚：**测试/开发过程中反复 `ingest` 同一篇论文**，每次生成新 `paper_id`，于是 583 个 chunk、98.97% 的索引覆盖率，全部是**两份文档自我复制 98 次**的产物。所谓"98 篇语料"，真实内容是 **2 篇机器人学习论文**。

**而且这 2 篇还都落在 `embodied`（冻结赛道）** —— 与你的 Post-Training 主轴（SFT/DPO/GRPO）**没有任何一篇相关**。

**前端层：❌ 零消费。** `grep` 全前端：没有任何页面或 service 调用 paper 端点，也没有 `/knowledge`、`/learning` 路由。

**所以对判断②的正确回答是：**

> **"做个知识库+agent"里的"做"是多余的，"接进来"是对的，而你还缺一条你原本没提到的 —— "灌料"。**
> 三件事要分开：**系统已有（别重建）／语料是假的（要真料）／前端没有（要入口）。**

### 2.3 诚实评估：它已经回答了什么、答不了什么（第四版口径）

| | 能力 | 证据 |
|---|------|------|
| ✅ | **"我今天学什么、做到什么算过"** | 今日页已渲染 `验收标准` / `学习目标` / `面试题主题` / **`指定资源`**（Hint 写着"只允许这 5 类来源"）—— 数据来自 `PlanDayOut`，实测 30/30 天都有 |
| ✅ | "我现在整体如何" | `/today` 五区 + `/api/transition/dashboard` |
| ❌ | **"我今天到底学到了什么"** | 没有内容位（§2.1）；`learning_logs` 表就是为这个设计的，却**没有前端** |
| ❌ | **"这个概念我在哪见过 / 卡住了问谁"** | 知识库无前端入口，且语料是假的（§2.2） |
| ❌ | 「指定资源」**不可点击** | 实测 `TodayBoard.tsx:428-436` 只渲染名字（如 `· Hugging Face LLM Course`），**没有 URL** ← 这正是你说的"不知道去**哪里**搜集"的直接原因 |

### 2.4 缺口定位：两个孤岛，缺一座桥

```
   ┌─────────────── 孤岛 A：输入（64 个写端点，都在）───────────────┐
   │  但都是「登记式」：建岗位 / 建博士目标 / 建项目 / 建简历版本      │
   │  缺「反思式」：今天学到什么、卡在哪、产出在哪                   │
   └────────────────────────────────────────────────────────────────┘
                                  ✗ 断

   ┌─────────────── 孤岛 B：内容（都躺在库里/文档里）───────────────┐
   │  · plan_days：30 天 × (目标/验收/面试题/资源) —— 有 UI ✅        │
   │  · paper RAG：5 端点 + LangGraph + 向量库 —— 无 UI ❌ 且语料假   │
   │  · docs/带你学-00/01/02：3 课讲义 —— 全库 grep 0 引用 ❌         │
   └────────────────────────────────────────────────────────────────┘
```

**这座桥的名字叫「学习日志」（`learning_logs`）** —— 它同时是**输入**和**证据**，而且后端早就建好了：

| 字段 | 含义 | 为什么它就是你要的"内容位" |
|------|------|----------------------------|
| `content` (Text, 必填) | 学习内容/产出（纯文本，**含反思总结**） | 这就是"我今天到底做了什么"的落点 |
| `duration_minutes` | 学习时长 | 支撑"投入 vs 产出"的 ROI 计算 |
| `artifact_url` | 学习证明链接（GitHub/视频/代码/博客） | 模型注释原话："**Reviewer 据此加分，未来作为 Portfolio 能力证据**" |

**闭环长这样**（每一环都已有代码，只有中间两个箭头缺 UI）：

```
今天学什么 (plan_days)  →  今天学到什么 (learning_logs)  →  卡住时问 (paper/ask)
     有 UI ✅                    无 UI ❌                       无 UI ❌ + 语料假 ❌
                                      ↓
                            谁来评 (reviewer)  →  证据 (artifact_url → Portfolio)
                               有 UI ✅                   有字段 ✅
```

> **结论**：你要的不是"更多功能"，是**让这条链在界面上转起来**。这是本轮唯一值得做的事。

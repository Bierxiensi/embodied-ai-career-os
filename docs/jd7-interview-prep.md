## 2. 三个真实缺口的「讲清权衡」清单（面试级，非训练级）

每个 30 分钟复习足够。目标：能口头讲清**机制 + 为什么这么设计 + 代价**。

### 2.1 MoE（专家路由 / 动态激活 / 负载均衡）
- **稀疏激活**：总参数大、每 token 激活少数专家（Qwen3-30B-A3B 总 30B、激活 ~3B）。
- **路由**：Top-k（通常 k=1–2），router 是轻量线性层，对 experts 做 softmax。
- **负载均衡**：auxiliary load-balancing loss + router z-loss；router collapse（多数 token 挤少数专家）现象与缓解（noise、capacity factor）。
- **与 dense 的区别**：参数量 vs 实际推理算力；微调时专家 specialization。
- 接 JD："贵司自研改进型 MoE-Transformer、动态专家激活与负载均衡——我研究过这套机制，正部署 Qwen3 MoE 验证。"

### 2.2 模型压缩与量化（INT8/INT4）
- **PTQ**：INT8（对称/非对称）、INT4；weight-only vs weight+activation。
- **主流方法**：GPTQ（二阶补偿）、AWQ（激活感知，保护重要权重）、FP8（H100 原生）。
- **KV Cache 量化**：Per-token / Per-channel，显存大头在 KV。
- **精度-时延-显存三角**：量化越狠 → 显存/时延降、精度风险升；敏感层（layernorm、部分 attention）不量化。
- 接 JD："模型压缩与加速、降低推理成本——我用 vLLM 部署时配置过 INT4/AWQ，理解精度-时延权衡。"

### 2.3 分布式训练（DP/TP/PP/ZeRO）
- **DP**：每张卡完整模型副本，gradient all-reduce；显存不降。
- **TP**：层内切分（attention head 维、FFN hidden 维），NCCL 高频通信，需高带宽（NVLink）。
- **PP**：按层切到不同卡，有流水线气泡（bubble），micro-batch 填充。
- **ZeRO（DeepSpeed）**：ZeRO-1 优化器状态分片 / ZeRO-2 +梯度 / ZeRO-3 +参数；显存收益大、通信增。
- **百亿组合**：TP（节点内 NVLink）+ PP（跨节点）+ DP + ZeRO-2/3。
- 接 JD："熟悉分布式训练——我梳理过 DP/TP/PP/ZeRO 的切分维度与显存公式，部署时按显存选 ZeRO-3。"

## 3. 文档智能叙事（把招投标评审系统映射成旗舰案例）

JD 核心工作 = 标准文本结构化解析 → 维度抽取 → 标准-企业-产业对齐 → 跨文档语义对齐。
用户真实项目 = 招投标评审系统（投标解析+报价抽取+废标审查，3000+ docs，cross-doc v3 64.3% → 接 DeepSeek Harness）。**高度同构**，直接对上 JD 的「标准条款拆解、标准比对分析、信息抽取」。

**STAR 草稿（口头讲 3 遍）：**
- **S**：招投标文件非结构化、废标条款散落，人工审查慢且漏（3000+ 份/季）。
- **T**：建全链路自动评审，解析投标、抽取报价、审查废标条件。
- **A**：cross-doc v3 单轮检索+LLM 判断（prompt v3）；对照 `eval_benchmark.json` 人工标注集评估；识别弱项（签字盖章 25% / 身份证 25% / 业绩缺失 33% 召回），正接入 DeepSeek Harness 作 Agent runtime 提召回。
- **R**：覆盖率 56%→90%（RAG 召回 56%→78%、Agent ReAct 56%→90%）；弱项类目召回向 >60% 推进。

> 这条叙事比「知识图谱」安全得多，且是**真实落地的信息抽取项目**——正好回答 HR 第二题。
